# Запуск скрипта извлечения

Это инструкция для Codex, а не дополнительные действия менеджера. Читать при запуске `ВЫГРУЗКА_презентации`. Скрипт находится в `../scripts/export_presentations.js` относительно этого файла. Для Node нет внешних зависимостей; в рабочем запуске используется JavaScript-среда `functions.exec` и подключенные Google-инструменты.

## Граница ответственности

Скрипт рекурсивно извлекает нативный текст, включая группы, таблицы и WordArt, сохраняет источник каждого блока, сортирует по геометрии и дням, игнорирует заметки докладчика, подготавливает точные повторы и запросы записи. Таблица остается цельным блоком с табуляцией между ячейками, чтобы одинаковые числа не потеряли связь со строками. Нестандартный порядок чтения и границы смысловых блоков проверяет Codex.

Скрипт не переводит, не распознает картинки, не принимает смысловое решение о полезности изображения, не загружает файлы в Drive и сам ничего не пишет в Google Sheets. Он формирует полный список `media`, включая вложенные картинки, фоны и превью, со статусом `pending`. Отбор, OCR, загрузка и сравнение визуальных дублей выполняются по основному SKILL.md. Запись производится подключенным инструментом после проверки плана.

На диске находится только код. Исходные данные, промежуточные блоки и запросы записи держать в `store()` внутри инструментальной сессии; не сохранять презентации, JSON с содержимым, таблицы и изображения на диск. Скрипт не требует Google-паролей, токенов или отдельной авторизации. Использовать уже подключенный аккаунт. При отсутствии `functions.exec` или нужного коннектора сообщить конкретное ограничение и использовать доступный разрешенный способ из скилла; не придумывать связь между локальным Node и MCP.

## 1. Загрузить код один раз

Определить абсолютный путь установленного скилла из текущего каталога навыков. В примере заменить `<SKILL_DIR>` на этот путь; это не параметр, который нужно спрашивать у менеджера. Полный текст кода не выводить модели.

```js
const r = await tools.exec_command({
  cmd: "Get-Content -LiteralPath '<SKILL_DIR>/scripts/export_presentations.js' -Encoding UTF8 -Raw",
  max_output_tokens: 16000
});
if (r.exit_code !== 0 || r.output.includes('tokens truncated')) throw Error('Не загружен полный код');
store('slidesExport.source', r.output);
const X = new Function(r.output + '\nreturn SlidesExport;')();
text({scriptVersion: X.VERSION});
```

В `new Function` передавать только доверенный установленный файл скрипта, никогда не содержимое презентаций или ответов внешних источников. В следующих вызовах восстанавливать `X` из `load('slidesExport.source')`. Если память сессии недоступна, снова загрузить код. `store` — память текущей сессии, а не постоянное хранилище между перезапусками приложения.

## 2. Получить структуру и сразу обработать ее

Карточку, папку и полный список исходных презентаций найти по СВОДНОМУ согласно SKILL.md. Перечисление папок и ограничения выдачи проверять до начала извлечения. На каждый запуск сформировать `jobKey`, содержащий ID текущей карточки; данные других проектов не переиспользовать. Презентации одного дня подавать в подтвержденном порядке.

```js
const X = new Function(load('slidesExport.source') + '\nreturn SlidesExport;')();
const response = await tools.mcp__codex_apps__google_drive_get_presentation({
  presentation_id: presentationId,
  fields: X.FIELDS
});
const extracted = X.extract(response, {language: 'ru', day: 1});
store(jobKey + '.deck.' + presentationId, extracted);
text({id: extracted.presentationId, slides: extracted.slides.length,
  blocks: extracted.blocks.length, media: extracted.media.length,
  issues: extracted.issues.length});
```

`presentationId`, `jobKey`, `language` и `day` в примере — переменные из текущего проекта, а не значения для копирования. Язык подтвердить по фактическому тексту нескольких слайдов, не только названию файла. Использовать `ru` или `en`. Скрипт может определить день из однозначного `День N` / `Day N` в названии, но не угадывает неизвестный день. Для презентации с несколькими днями передать подтвержденную карту `slideDays: {slideObjectId: dayNumber}`. Программа не считает упоминание «День 2» в программе первого дня автоматическим началом второго дня: такое совпадение выдается на проверку.

При другом имени инструмента обнаружить его актуальную схему. Не использовать outline или `get_presentation_text` вместо полного ресурса. Если источник изменился во время работы, повторно прочитать измененную презентацию; просроченный `contentUrl` обновлять по исходному объекту, не искать по имени. `FIELDS` исключает notes из запроса; если коннектор все же вернул notes, код их не обходит.

**Не делать `text(response)`, `text(extracted)` или `text(plan)` на полном наборе.** Данные должны идти от коннектора в скрипт и запросы записи, а модели показывать небольшие порции текста для смысловой проверки, счетчики и исключения.

## 3. Проверить текст и картинки

`X.buildPlan(extractions)` принимает список результатов и возвращает черновик. Дни сортируются численно, порядок презентаций внутри дня сохраняется. `X.summary(plan)` возвращает короткие счетчики; `X.page(items, offset, limit)` выводит не более 100 записей. Для первичной проверки достаточно 10–20.

- `extracted.blocks`: исходный `rawText`, подготовленный `text`, координаты, ID презентации/слайда/элемента. Проверить начало, конец, сложные группы, таблицы и смысловые границы; при необходимости исправить `text` или разделение блоков в рабочем объекте, сохранив связь с исходником. Нельзя улучшать формулировки и переводить.
- `extracted.issues`: неоднозначные числа, автоматически создаваемые маркеры списков, противоречия дней, повернутый текст и унаследованные элементы. После проверки вызвать `X.resolveIssue(extracted, id, {reason, blockText?, excludeBlock?})`. `blockText` заменяет текст только проверенного блока. Не закрывать вопросы без проверки.
- Числа с явно указанной валютой/ценой нормализуются автоматически. Группы цифр без контекста остаются на проверку, включая NBSP: это может быть телефон или независимые числа. Подтвержденную цену `7 990` заменить на `7990` через `blockText`; телефон, дату и независимые числа сохранить с объяснением.
- Точные повторы содержимого целого слайда и длинных блоков удаляются программно. Повтор короткой подписи или числа в измененном окружении сохраняется в черновике и появляется в `plan.review`. Сгруппировать через `X.reviewGroups(plan)`; после сравнения передать `duplicateDecisions: {[blockId]: 'keep' | 'drop'}` в `buildPlan`. Практически одинаковые, но не точные повторы проверяет Codex. Нельзя удалять число только потому, что оно уже встречалось.
- Текст master/layout не вставляется автоматически: проверить, виден ли он на реальном слайде. Видимый блок разместить через `X.placeInherited(extracted, blockOrMediaId, actualSlideId)`, затем закрыть соответствующий issue; невидимый placeholder исключить. Для унаследованного изображения также подтвердить видимость перед решением.
- `extracted.media`: каждый объект остается в списке независимо от удаления повторного текста слайда. `contentUrl` использовать для нужного оригинала; не выводить все URL в отчет. Не считать равенство имени, alt-текста или URL достаточным доказательством содержательной эквивалентности разных изображений.

Для каждого изображения Codex вызывает `X.decideMedia(extracted, mediaId, decision)` после фактического действия:

```js
// Декоративная/неподходящая картинка после просмотра:
{status: 'excluded', reason: 'Фото без значимого переводимого текста'}
// Уже сохранены и файл, и текст:
{status: 'reused', reason: 'Подтвержден тот же визуал и текст',
 fileUrl: existingDriveUrl, ocrRange: existingOcrLocation}
// Новый оригинал загружен, OCR визуально проверен:
{status: 'included', reason: 'Карточка с переводимым текстом',
 fileUrl: uploadedDriveUrl, language: 'ru', ocrVerified: true,
 blocks: ['Первый смысловой блок', 'Второй смысловой блок']}
// Реальный незавершенный пункт:
{status: 'blocked', reason: 'Конкретная проблема доступа или распознавания'}
```

`blocks` должны содержать только проверенный OCR. Если в OCR остаются группы независимых чисел, после проверки можно указать `numbersReviewed: true`; это не разрешение пропускать исправление цен. При совпадении OCR с нативным текстом скрипт удаляет полные совпадающие блоки; частичные совпадения проверяет Codex. Для переиспользованного OCR на текущем перестраиваемом листе обеспечить сохранение его единственного существующего блока по SKILL.md.

После решений пересобрать план. `plan.complete === true` означает только отсутствие открытых пунктов в подготовленном плане; это **не подтверждение записи, оформления или завершения всей выгрузки**. Не менять `complete` вручную. Общее завершение разрешено только после проверок основного скилла.

## 4. Подготовить запись и сверить результат

Сначала проверить текущие метаданные, заголовки, формулы, объединения, существующие переводы и служебные места. Ниже быстрый путь для пустого диапазона или точного повторного запуска. Если требуется перестройка существующих строк, сохранение единственного OCR, устранение старого хвоста или изменение соответствия переводу, применять процедуру безопасной записи из SKILL.md; не обходить отказ программы случайным пустым `before`.

1. Получить актуальный `sheetId`. `startRow` — первая строка данных с учетом существующих служебных строк, не всегда 2.
2. Прочитать A:B от `startRow` до конца занятого диапазона либо до конца будущего результата, если он длиннее. Для проверки формул использовать `FORMULA`; дополнительно проверить CellData там, где важны ссылки/форматирование/валидация/объединения. Дополнить отсутствующие пустые строки `[]` до длины результата.
3. `const prepared = X.prepareWrite(plan, {sheetId, startRow, before, reviewed: true});`
4. Сохранить `prepared` в `store`. Через актуальный `google_drive_batch_update_spreadsheet` передать `prepared.requests` в контролируемых пакетах, не выводя весь JSON. Подтвердить успешность каждой порции. Скрипт меняет только значения нужной языковой колонки и желтую заливку строк дней; не создает лист, не вставляет/удаляет строки, не очищает хвост и не форматирует таблицу целиком.
5. Перечитать тот же диапазон также в `FORMULA`, чтобы сравнить соседние формулы с тем же представлением до записи. Выполнить `X.verifyReadback(prepared, after)` и вывести только результат проверки. Отдельно сверить желтую заливку по CellData и прочие требования основного скилла: проверка значений не доказывает сохранность оформления.

Не использовать быстрый путь поверх формул, существующего другого текста, конфликтов языкового выравнивания или старого содержимого после конца нового результата. Для безопасного обновления такого листа Codex должен сначала подготовить и проверить индивидуальное соответствие строк.

## Проверка самого скрипта

```powershell
node --test '<SKILL_DIR>/scripts/export_presentations.test.js'
```

Тесты не обращаются к сети и не изменяют таблицы. При изменениях дополнительно проверять чтение реальной презентации через подключенный коннектор без записи; успешный тест текстового извлечения не считать выполненной обработкой изображений.
