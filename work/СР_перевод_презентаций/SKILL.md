# СР_перевод_презентаций

## Вход

Нужны две ссылки:

1. Папка Google Drive с Google-презентациями.
2. Google-таблица с переводами.

Если пользователь вызвал скилл и не дал обе ссылки, сразу запросить недостающие ссылки и не начинать работу.

## Жесткие правила

- Работать только через подключенный Google Drive connector под аккаунтом пользователя.
- Не использовать публичные/анонимные скачивания, `gdown`, `wget`, `requests`, браузерный scraping или неаутентифицированные Drive API.
- Работать прямо в исходных Google-презентациях.
- Не создавать копии, если пользователь прямо не попросил.
- Google-таблицу с переводами не изменять.
- Заметки докладчика не переводить и не менять.
- Менять только текст на видимых слайдах.
- Не менять шрифты, размеры, цвета, расположение, оформление, картинки и любые другие элементы дизайна.
- Тексты менять строго по таблице. Самостоятельно ничего не переводить.
- Делать презентации по одной: заменить, проверить, сохранить, перейти к следующей.

## Чтение переводов

1. Открыть Google-таблицу через Google Sheets connector.
2. Считать весь диапазон `A:B` до конца фактических данных, а не только верхние строки.
3. Столбец `A` считать исходным русским текстом, столбец `B` - готовым переводом.
4. Пустые строки пропускать.
5. Сохранять многострочные переводы как многострочные тексты.
6. Если в таблице есть несколько вариантов одного русского фрагмента, использовать все варианты.
7. На основе всех непустых пар `A:B` подготовить машинный список замен. Нельзя выбирать строки вручную как основной метод: ручной выбор почти всегда оставляет короткие подписи, названия техник и тексты внутри групп.

## Обработка папки

1. Открыть папку через Google Drive connector.
2. Найти все Google-презентации в папке.
3. Если пользователь попросил исключить отдельную презентацию, пропустить ее.
4. Обрабатывать презентации по одной.

## Инвентаризация видимого текста

Перед заменой и после замены обязательно собрать полный список видимого текста обычных слайдов:

1. Использовать `get_presentation` как источник структуры, а не `get_presentation_outline`.
2. `get_presentation_outline` можно использовать только для быстрой навигации и предварительного просмотра. Он не является источником истины: если в outline у слайда `text = null`, но `pageElementCount > 0`, такой слайд считается подозрительным и должен быть проверен через полный объект презентации или `get_slide`.
3. Для каждого обычного слайда фиксировать:
   - номер слайда;
   - `pageObjectId`;
   - `objectId` элемента;
   - сам видимый текст;
   - есть ли в нем кириллица.
4. Рекурсивно обходить все контейнеры:
   - обычные shapes;
   - tables и все ячейки таблиц;
   - `elementGroup.children`;
   - вложенные группы любой глубины, а не только первый уровень.
5. Не учитывать:
   - `notesPage`;
   - `speakerNotesObjectId`;
   - objectId страниц заметок;
   - speaker notes;
   - filenames;
   - image title/alt text.
6. Русский текст в заметках докладчика допустим и не является ошибкой для этого скилла.

## Автогенерация замен из A:B

1. Для каждой непустой пары `A:B` создать точную замену полного текста `A` на `B`.
2. Для многострочных пар `A:B` дополнительно создать замены для коротких самостоятельных фрагментов из `A`, когда они встречаются на слайдах отдельно:
   - названия техник;
   - короткие заголовки;
   - подписи к изображениям;
   - названия блоков;
   - тексты кнопок или ярлыков;
   - цены и тарифы.
3. Фрагментные замены брать только из строк таблицы `A:B`. Самостоятельно переводить нельзя. Если нужен фрагмент английского текста, брать соответствующую строку или часть из колонки `B`.
4. Применять замены ко всем обычным `pageObjectIds`, исключая заметки.
5. Если запросов слишком много, делить `batchUpdate` на партии примерно по 80-150 замен.
6. После каждой партии проверять `occurrencesChanged`; нулевые срабатывания допустимы только если текст действительно отсутствует на видимых слайдах.

## Правильный способ замены

Для каждой презентации:

1. Получить полный объект презентации, не только outline.
2. Собрать `objectId` всех обычных слайдов.
3. Собрать инвентаризацию видимого текста по правилам выше.
4. Делать `replaceAllText` только с `pageObjectIds`, где перечислены `objectId` слайдов.
5. Никогда не запускать глобальный `replaceAllText` без `pageObjectIds`: он может затронуть заметки докладчика.
6. Не включать в `pageObjectIds` `notesPage` и objectId вида `...:notes`.
7. Сначала применить точные пары из таблицы.
8. Затем применить фрагментные замены для длинных блоков, которые могут быть разбиты переносами строк, разными text runs или элементами группы.
9. Затем применить обязательные замены цен, если они встречаются.

Обязательная схема цен:

```text
19 900₽ -> $500
19 990₽ -> $500
15 990₽ -> $399
9 990₽ -> $250
5 990₽ -> $199
7 990₽ -> $200
4 990₽ -> $99
2 990 руб. -> $59
59$ -> $59
500$ -> $500
250$ -> $250
200$ -> $200
```

## Важная проверка полноты

Краткий outline недостаточен: он может пропускать тексты внутри групп, отзывов и некоторых дочерних элементов.

После каждой презентации повторно получать презентацию и проверять полный видимый текст слайдов рекурсивно:

- `slides[].pageElements[].shape.text.textElements[].textRun.content`
- `slides[].pageElements[].elementGroup.children[].shape.text.textElements[].textRun.content`
- при наличии вложенных групп обходить их рекурсивно
- при наличии таблиц проверять текст ячеек

Исключать из проверки:

- `slideProperties.notesPage`
- speaker notes
- названия файлов/презентаций
- `title` / alt-тексты картинок

Если осталась кириллица в видимом тексте слайдов:

1. Найти точный русский фрагмент.
2. Найти его перевод в таблице, включая нижние строки.
3. Если длинный блок не находится целиком, разбить его на короткие фрагменты: имя, первая фраза, второй абзац, текст в скобках и т.д.
4. Если текст находится внутри группы, все равно заменять его через `replaceAllText` по `pageObjectIds` обычных слайдов.
5. Сделать дополнительный `batchUpdate` только по `pageObjectIds` слайдов.
6. Повторить проверку.
7. Нельзя завершать работу, если в инвентаризации видимого текста обычных слайдов осталась кириллица, кроме случаев, когда пользователь явно сказал оставить конкретный текст.

## Контрольный проход

После исправлений сделать контрольный проход:

1. Повторно применить ключевые русские фразы из таблицы к `pageObjectIds` слайдов.
2. Если `occurrencesChanged` больше нуля, значит был найден и исправлен остаток.
3. Повторять, пока по известным русским фразам из таблицы не будет нулевых срабатываний.
4. При сомнении открыть конкретный проблемный слайд через Google Slides connector и проверить `elementGroup.children`, потому что именно там часто остаются тексты отзывов.
5. Для коротких строк вроде `Техника по смоченной бумаге (по-сырому)` и `Техника «Вкрапление облаков и волн»` делать отдельный контрольный поиск, даже если длинный блок из таблицы уже был заменен.

## Критерий готовности

Презентация считается обработанной только если:

1. Все обычные слайды перечитаны после замен.
2. В видимом тексте обычных слайдов нет кириллицы.
3. Тексты в `notesPage` и speaker notes не изменялись.
4. Дизайн, изображения, порядок слайдов и структура презентации не менялись.

## Финальный ответ

Кратко сообщить:

- какие презентации обработаны;
- что работал прямо в исходниках, без копий;
- что Google-таблица не изменялась;
- что заметки докладчика не переводились;
- что проверка делалась по полному содержимому слайдов, включая сгруппированные элементы, а не только по outline;
- что выполнен контроль на отсутствие кириллицы в видимом тексте обычных слайдов.
