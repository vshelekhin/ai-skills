# Сдваивание регистрационных писем

Работать непосредственно в существующей Google Sheets-таблице через подключённый Google Drive / Google Sheets connector. Не просить пользователя копировать письма в чат.

Перед составлением писем полностью прочитать [references/merge-rules.md](references/merge-rules.md). Все редакторские формулировки, сроки доступа, правила соцсетей и подписки из справочника обязательны.

## Что создать

- версия «сегодня» = письмо №0-а + письмо №1;
- версия «завтра» = письмо №0-а + письмо №1-А;
- русскую версию записать в указанный пользователем русский столбец, английскую — в указанный английский столбец;
- начинать запись со строки заголовка письма №0-а, если пользователь не указал другую строку.

Если №1-А отсутствует, создать только версию «сегодня» и сообщить об этом. Не придумывать письмо №1-А.

## Несколько проектов

Если пользователь прислал несколько таблиц, обрабатывать их строго по одной в указанном порядке:

1. найти и прочитать источники одного проекта;
2. проверить целевой диапазон;
3. записать обе версии этого проекта;
4. перечитать и полностью проверить результат;
5. только после успешной проверки переходить к следующему проекту.

Не выполнять чтение, запись или проверку разных проектов параллельно. Внутри одного проекта допустимы несколько одновременных безопасных поисковых чтений.

## Входные данные

До записи должны быть известны:

- ссылка или ID таблицы;
- целевой лист, определённый по ссылке и актуальным метаданным;
- целевые языковые столбцы;
- строка, с которой пользователь просит начать запись, либо однозначная строка №0-а.

Не переносить буквы столбцов, строки или `sheetId` из другого проекта. Если пользователь назвал C для русского и D для английского, писать только в C:D. Не выбирать другие пустые столбцы.

## Порядок работы с одним проектом

### 1. Зафиксировать таблицу

1. Получить актуальные метаданные.
2. Зафиксировать spreadsheet ID, точное видимое название листа, `sheetId`, размеры сетки и разрешённые столбцы.
3. Использовать точное название листа из метаданных; `gid` из URL не считать названием листа.
4. Читать ограниченные диапазоны; один поиск не должен охватывать более 50 000 ячеек.

### 2. Найти исходные письма

Искать варианты написания `№0-а`, `№0-a`, `0-а`, `0a`, затем №1 «СЕГОДНЯ» и №1-А «ЗАВТРА». Подтвердить назначение по смыслу, а не только по номеру:

- №0-а содержит бесплатный и платный варианты участия;
- №1 относится к регистрации и старту сегодня;
- №1-А относится к регистрации и старту завтра.

Определить границы по следующему заголовку письма и прочитать каждый блок целиком: тему, прехэдер, тексты, ссылки, изображения или плейсхолдеры, пустые строки и подпись.

Если №0-а не найдено, выполнить поиск по всему разрешённому диапазону по номеру и смысловым фразам: `бесплатное участие`, `free participation`, `варианты участия`, `тариф`, `9,99`, `записи эфиров доступны`. Только если отсутствие подтверждено и в начале серии есть письмо №0 подтверждения регистрации, можно использовать строку №0 как стартовую строку, взять проектные факты из №1/№1-А и добавить обязательный стандартный блок вариантов участия из справочника. Кратко отметить это пользователю. Если точка начала всё ещё неоднозначна — уточнить до записи.

При нескольких правдоподобных блоках, четырёх исходных письмах или промежуточном письме только с материалами не угадывать: показать точные строки-кандидаты и задать один вопрос.

### 3. Определить форму записи

До записи прочитать точный целевой диапазон, включая значения и форматирование.

- Если шаблон построчный, сохранить построчную сетку и намеренно пустые строки.
- Если письмо хранится в одной ячейке, записать его в одну ячейку с настоящими переносами строк.
- Не вставлять и не удалять строки или столбцы.
- Не перезаписывать непустой целевой диапазон без явного разрешения.

### 4. Собрать письма

Не склеивать тексты механически. Удалить повторы и расположить блоки в порядке из справочника. Проектные факты, названия, подарки, личный кабинет, содержание уроков, изображения и эфирную ссылку брать только из текущего проекта.

Обязательно различать версии:

- сегодня: эфир сегодня и ссылка из исходника;
- завтра: эфир завтра, ссылку не переносить, написать, что она придёт в следующем письме.

Не переводить новые тексты без прямой просьбы. Если на листе есть RU и EN источники, объединять каждую языковую версию из её исходного столбца.

### 5. Записать только разрешённые ячейки

1. Ещё раз перечитать точный целевой диапазон.
2. Составить карту `ячейка -> значение`, включая пустые строки.
3. Записать связанные значения одним точным `updateCells` по актуальному `sheetId`, меняя контент только в разрешённых столбцах.
4. Исходные письма и соседние столбцы не менять.
5. Включить перенос текста `WRAP` во всём итоговом диапазоне.
6. Заголовок каждой объединённой версии в обоих языковых столбцах сделать жирным и залить чистым жёлтым `#ffff00`. После записи проверить effective format. Если заголовок унаследовал стиль ссылки, только в строке заголовка убрать синее подчёркивание и вернуть обычный чёрный текст.

### 6. Проверить до перехода к следующему проекту

Перечитать весь изменённый диапазон и убедиться:

- созданы обе нужные версии и записаны в правильные столбцы;
- тема и прехэдер стоят в начале;
- версия сегодня содержит эфирную ссылку ровно в обеих языковых версиях, версия завтра её не содержит;
- RU-время и EN-время соответствуют справочнику или подтверждённому исключению серии;
- для 5-дневного марафона указано 8 дней, для 3-дневного — 7 дней, по одному разу в каждом объединённом письме каждого языка;
- Telegram-чат удалён из RU и EN;
- в RU нет соцсетей;
- в EN стоит только актуальный Instagram из справочника;
- нет тарифа «Комфорт», 9,99$, бонусных долларов, розыгрыша призов и формулировок `no limits` / `без ограничений`;
- сохранены нужные проектные факты, ссылки в формате `[Название] (URL)`, плейсхолдеры и переносы;
- оба заголовка в RU и EN жирные, чисто жёлтые и не выглядят гиперссылками;
- весь итоговый диапазон использует `WRAP`;
- вне разрешённого диапазона ничего не изменено.

## Финальный ответ

После одного проекта кратко сообщить, что он полностью готов и проверен. Если проектов несколько, после завершения всех проектов выдать список `название проекта — ссылка на таблицу`. Полные тексты писем в чат не дублировать, если пользователь этого не просил.
