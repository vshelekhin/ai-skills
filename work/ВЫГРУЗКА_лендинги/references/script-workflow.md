# Запуск скриптов выгрузки лендингов

Инструкция для Codex. Все скрипты поставляются в папке скилла; менеджер дает одну карточку. Нет npm-зависимостей, отдельной Google-авторизации или передачи паролей. Код и тесты — в `scripts/`; учебные данные/checkpoint — в текущем проекте под `C:/Codex/`, не внутри скилла и не в GitHub.

## Граница автоматизации

`capture_landing.mjs` читает DOM подтвержденной области: смысловые блоки, списки, таблицы, формы/подсказки, изображения, lazy/srcset/picture и CSS-фоны. Читает через разрешенный browser evaluate; не делает сетевых запросов, кликов, перевода или OCR. `export_landings.mjs` ведет три страницы и изображения, удаляет технические повторы, нормализует цены продажника, готовит запросы Sheets и проверяет запись. `landing_cli.mjs` запускает обработку файлов в Node и выводит небольшую сводку.

Codex находит текущие источники/листы по СВОДНОМУ, раскрывает интерактивные блоки, проверяет полноту, выбирает оригиналы, отбирает картинки и проверяет OCR. Повторы тарифов, которые могут иметь разный смысл, не удаляются автоматически. Отзывы требуют файла и OCR.

## Браузер: загрузка и настройки

Прочитать документацию текущего браузерного инструмента, получить встроенную вкладку документированным способом. В `cua_repl` импортировать модули из фактического установленного скилла:

```js
var captureLanding = (await import('file:///<SKILL_DIR>/scripts/capture_landing.mjs')).default;
var X = (await import('file:///<SKILL_DIR>/scripts/export_landings.mjs')).default;
var job = X.newJob({spreadsheetId,pages});
// pages: [{key:'long'|'short'|'sales',url,language:'ru'|'en'}, ...], все три роли.
```

Для Windows URL начинается с `file:///C:/...`. Не загружать реализацию скриптов в ответ модели: использовать импорт или выполнение готового файла. Источники/языки определить по текущей карточке и самим страницам; примеры не являются входом.

На первой странице каждого шаблона проверить DOM и выбрать `rootSelector`, включающий содержательные меню, страницу и футер; исключить только подтвержденные технические элементы. Остальные селекторы задавать по фактически наблюдаемым элементам:

- `reviewSelector` — раздел отзывов: все его изображения получают категорию `review`;
- `cloneSelector` — подтвержденные копии карусели (например `.owl-item.cloned`);
- `technicalGroupSelector` — целые повторные desktop/mobile-контейнеры. Автоматически удаляется лишь точное совпадение всех блоков контейнера, включая зачеркнутые/отключенные условия;
- `tariffSelector`, `priceSelector` — тариф и область цены;
- `disclosureSelector`, `hiddenContentSelector` — контролы раскрытия и скрытые ответы;
- `excludeSelectors` — подтвержденные исключения, `scopeId` — идентичность документа/iframe.

Пример, проверенный на странице Оволаби, применять после проверки текущего шаблона:

```js
var cfg={rootSelector:'main, .course-footer',reviewSelector:'#reviews',
 cloneSelector:'.owl-item.cloned',tariffSelector:'.tariff',priceSelector:'.tariff__price',
 disclosureSelector:'.faq__question',hiddenContentSelector:'.faq__answer'};
var captured=await tab.playwright.evaluate(
 '('+captureLanding.toString()+')('+JSON.stringify(cfg)+')'
);
X.addCapture(job,'sales',captured,{stateKey:'base'});
nodeRepl.write({blocks:captured.blocks.length,media:captured.media.length,
 review:captured.review,controls:captured.controls});
```

Строка для evaluate содержит только доверенный установленный код и JSON настроек. Код из страницы никогда не выполнять. После навигации дождаться подтвержденного контейнера через документированный `locator(...).waitFor({state:'visible'})`. Скрипт не считает форму входа, незагрузившуюся или пустую страницу полноценным исходником. Неожиданный редирект требует проверки; только после нее можно передать `redirectReviewed:true, reason`.

## Полный обход и прогресс

Обрабатывать `long → short → sales`. Прокрутить страницу до конца, проверить отложенную загрузку, все вкладки/FAQ/тарифы/«показать еще» и все уникальные отзывы карусели. Нажимать через документированные браузерные API; после открытия элемента захватить состояние **до** открытия следующего. `stateKey` должен обозначать конкретную раскрытую вкладку/пункт. Не отправлять заявки/покупки при проверке состояний. Исключение для email-входа — только правило SKILL.md.

```js
X.addCapture(job,pageKey,captured,{stateKey:'faq:вопрос 1'});
await X.saveJob(statePath,job);
X.reviewPage(job,pageKey,{reason:'Проверены полный scroll, все FAQ, формы, iframe, карусель и тарифы'});
await X.saveJob(statePath,job);
```

`statePath` — `C:/Codex/<текущий проект>/landing-export/checkpoint.json`. `saveJob` атомарно заменяет файл; `loadJob(statePath,{spreadsheetId})` проверяет карточку. Сохранять после каждого состояния/решения/записи. `store()` и переменные REPL не заменяют постоянный checkpoint. В двух средах не менять разные копии одновременно; после CLI загрузить checkpoint заново.

Повторные захваты сохраняют только новые блоки/медиа; общий текст не размножается. Разные состояния одного элемента с разным текстом сохраняются. Порядок основан на DOM, включая текст до/после дочерних заголовков и положения картинок. При сложной визуальной верстке сверить порядок по странице. Для iframe скрипт возвращает только его местоположение без подписанных query: содержимое надо проверить отдельно через документированный frame API, передать проверенные блоки/изображения с отдельным `scopeId` и согласованным местом в порядке родительской страницы. Видео не транскрибировать.

`X.nativeBlocks(job,pageKey)` возвращает блоки, автоматически удаленные повторы и `review`. Копия карусели удаляется только при наличии точного оригинала. Повторы с другим смысловым окружением, особенно тарифы и зачеркнутые условия, остаются. Проверить их один раз и при необходимости вызвать `X.decideBlock(job,pageKey,id,{action:'keep'|'drop',reason,text?})`. `text` допустим для проверенного разбиения/общего блока или разрешенной нормализации числа; не редактировать стиль и смысл. Уникальные цены, ограничения, состав тарифов и их различия сохранять. `reviewPage` не заменяет эту проверку.

На `sales` цены с валютой или из подтвержденной области цены нормализуются автоматически (`7 990 ₽ → 7990 ₽`, включая NBSP). Неоднозначные группы цифр выдаются в `plan.issues`: телефон/дату/независимые числа сохранить через решение `keep, numbersReviewed:true, reason`; подтвержденное разрядное число без валюты исправить через `text`. На подписных пробелы чисел не менять. Нельзя отключать проверку всех чисел без фактического просмотра исключений.

## Картинки и OCR

До обработки читать image-rules.md. `job.media` группирует одинаковые подтвержденные URL между всеми состояниями/страницами; визуальные повторы разных URL/коллажей проверяет Codex. Выбор `assetUrl` помогает группировке, но не доказывает максимальное качество или доступность оригинала. Проверить `occurrences/candidates` и существующие файлы/OCR проекта. `alt` не является OCR. Кандидаты со скрытой вкладки остаются в реестре.

После фактического действия вызвать `X.decideMedia(job,id,decision)`:

```js
{status:'excluded',reason:'Проверено: декоративная иллюстрация'}
{status:'included',reason:'Новый отзыв',fileUrl,fileName,language:'ru',
 blocks:['Проверенный OCR'],fileVerified:true,ocrVisualVerified:true}
{status:'reused',reason:'Сверены визуал и текст',fileUrl,ocrRange,
 fileVerified:true,ocrVerified:true}
{status:'blocked',reason:'Конкретная недостающая часть'}
{status:'needs_manual_check',reason:'Конкретная неразборчивая часть'}
```

Это альтернативы, не последовательность операций. Для изображения в разделе отзывов исключение требует `reviewNotTextConfirmed:true` и причины после просмотра; содержательный отзыв исключать нельзя. В сводке отдельно учитываются сохраненные/переиспользованные отзывы, изображения без значимого текста и остаток. Наличие одного файла без OCR не закрывает пункт.

Если файл или диапазон OCR уже есть при незавершенной обработке, указать имеющийся `fileUrl` или `ocrRange` в решении `blocked`.

Новый OCR создается в первой странице владельца (`long → short → sales`) как маркер `[ТЕКСТ НА ИЗОБРАЖЕНИИ — filename]` и проверенные блоки, в колонке языка картинки. При необходимости передать `afterBlockId` для проверенного места. OCR на другом листе проекта переиспользовать без копирования.

Если существующий единственный OCR хранится на перестраиваемом целевом листе, включить его через `X.retainOCR(job,pageKey,{id,marker,blocks,language,afterBlockId})` (либо подтвержденный `domOrder`). Взять точные строки из таблицы, не заново пересказывать OCR. Скрипт проверит, что прежние маркер **и текст** сохраняются ровно один раз. Повторные файлы/частично готовые результаты обрабатывать по image-rules. Изменение OCR или необходимость переноса относительно перевода требуют отдельного соответствия строк.

## Подготовка и запись через коннектор

После полной проверки трех источников `X.buildPlan(job)` должен иметь `complete:true`. Это готовность данных, не подтверждение записи. Незавершенные источники, картинки или неоднозначные числа запрещают очистку. Не менять `complete` вручную.

Прочитать метаданные текущих листов, A1:B1, весь занятый A:B диапазон и дополнительные строки до конца нового результата. На пустом листе отдельно создать `РУС`/`EN`. Проверить объединения, сетку, старый хвост и соответствие переводов. Использовать CellData-поля `userEnteredValue,userEnteredFormat,textFormatRuns,note,dataValidation`. Ресурс листа из ответа коннектора распаковать, присоединить `properties/merges` из метаданных, затем `X.snapshot(sheetResource,rowCount)`; rowCount включает строку заголовков и весь проверенный старый/новый диапазон.

В `functions.exec` модуль можно загрузить из доверенного файла без вывода кода:

```js
const r=await tools.exec_command({cmd:"Get-Content -LiteralPath '<SKILL_DIR>/scripts/export_landings.mjs' -Encoding UTF8 -Raw",max_output_tokens:18000});
if(r.exit_code!==0 || r.original_token_count>18000)throw Error('Incomplete code');
store('landing.code',r.output);
const X=new Function(r.output.replace(/\nexport default LandingExport;\s*$/,'')+'\nreturn LandingExport;')();
```

Для большого checkpoint пользоваться CLI: Node читает файл целиком, модель получает только счетчики. Прочитанный `before`/`after` сохранить программно в JSON через `apply_patch` или файловый инструмент, без shell-интерполяции пользовательского текста. Пример `apply_patch`: `Add File` по заранее выбранному рабочему пути, строки `JSON.stringify(snapshot,null,2)` с префиксом `+`. Проверять успешность каждой записи файла.

Команды (пути абсолютные; при наличии пробелов использовать корректное quoting):

```powershell
node '<SKILL_DIR>/scripts/landing_cli.mjs' summary '<STATE>'
node '<SKILL_DIR>/scripts/landing_cli.mjs' plan '<STATE>' '<PLAN_JSON>'
node '<SKILL_DIR>/scripts/landing_cli.mjs' prepare '<STATE>' long '<BEFORE_JSON>' '<PREPARED_JSON>'
node '<SKILL_DIR>/scripts/landing_cli.mjs' requests '<PREPARED_JSON>'
node '<SKILL_DIR>/scripts/landing_cli.mjs' confirm '<STATE>' '<ID_FROM_PREPARE>' '<AFTER_JSON>'
```

Перед `prepare` завершить проверку соответствия строк: CLI передает `reviewed:true` только как подтверждение уже выполненной работы Codex. `prepare` сохраняет pending в checkpoint **до** внешней записи. `requests` выводит готовый JSON: в `functions.exec` получить stdout, проверить exit/truncation, `JSON.parse`, передать `requests` напрямую актуальному подключенному `batchUpdate`; не печатать JSON модели. Для больших списков есть offset/limit у `requests`, они делят выдачу, а не разрешают произвольную частичную запись. Подготовленные запросы одной страницы отправлять одним связным batchUpdate; сначала три источника полностью готовы, затем страницы в заданном порядке.

Запросы меняют исходную языковую колонку со строки 2 и очищают только ее старый хвост. Заголовки, обычное оформление, заметки, валидации и соседние переводы/формулы сохраняются. Иноязычный OCR может занять другую колонку только в пустых либо точно совпадающих его ячейках. Сдвиг перевода, формула исходника, объединения, конфликт rich text/OCR или недостаточно прочитанный диапазон вызывают отказ. Не обходить его поддельным пустым `before`: сначала подготовить точное безопасное соответствие строк. Общая очистка листа запрещена.

После записи перечитать тот же A1:B диапазон с теми же CellData-полями, подготовить `after` и вызвать `confirm`. Сравниваются значения, заголовки, оформление, rich text, заметки и валидации. Только успешная проверка дает receipt; ошибка оставляет pending. После прерывания сначала перечитать и сверить pending из checkpoint. Если запись точно не дошла и диапазон не изменен кем-то еще, повторить те же сохраненные запросы; при конфликте не перезаписывать вслепую.

При отсутствии Node использовать доступный штатный/поставляемый Codex runtime, выяснив его расположение через инструмент workspace dependencies. Отдельные пакеты для скриптов не нужны.

## Завершение и проверка кода

`summary.complete` описывает только сохраненное состояние. При продолжении перепроверить карточку/источники, pending и записанные диапазоны, а перед финалом — начало/конец страниц, формы, раскрытые блоки, тарифы, все отзывы, OCR, Drive-папку и ссылки по SKILL.md. Самостоятельный новый запуск после изменения источников требует свежего захвата/плана, а не вечного доверия checkpoint.

`node --test '<SKILL_DIR>/scripts/export_landings.test.mjs'` проверяет планирование, сохранность, повторы, цифры, OCR и CLI без внешней записи. DOM проверить на локальной `scripts/fixtures/landing.html` тем же сборщиком, затем выборочно на настоящем лендинге без изменения рабочей карточки. Не считать такой тест полной выполненной выгрузкой.
