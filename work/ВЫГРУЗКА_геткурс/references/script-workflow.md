# Скриптовая выгрузка GetCourse

Инструкция для Codex. Менеджер по-прежнему дает одну карточку. Скрипты находятся внутри этого скилла, устанавливаются вместе с **всей папкой** скилла и не требуют npm-пакетов, отдельных Google-токенов или передачи паролей.

## Что автоматизировано

- `scripts/capture_page.mjs`: чтение подтвержденных областей открытой страницы, абзацы, списки, таблицы, ссылки, изображения (`src`, lazy-атрибуты, `srcset`, `picture`, CSS-фоны). Только чтение DOM через разрешенный браузерный инструмент; никаких сетевых запросов, кликов, скрытых API, cookies или ответов за ученика.
- `scripts/export_getcourse.mjs`: реестр корней/подтренингов/уроков, удаление повторных ссылок с сохранением принадлежности и порядка, прогресс, подготовка Google Sheets `batchUpdate`, сравнение результата и учет изображений.
- Браузерные переходы выполняет Codex через `cua_repl`, загрузку изображений и запись — подключенные инструменты. Скрипт **сам не переводит, не делает OCR и не решает, какие картинки полезны**. Обычный повтор текста в разных уроках сохраняется.

## 1. Загрузка и состояние

Сначала выполнить обнаружение текущей карточки, языка, всех корней, трех вкладок и общей папки по SKILL.md. Идентификаторы примеров и прошлых проектов не копировать. Прочитать документацию текущего браузерного инструмента. По умолчанию использовать видимый встроенный браузер; вход выполняет пользователь, если он действительно нужен.

В `cua_repl` импортировать модули по абсолютному пути **установленного** скилла (путь определить самостоятельно). Пример после получения `tab` документированным способом:

```js
var capturePage = (await import('file:///<SKILL_DIR>/scripts/capture_page.mjs')).default;
var X = (await import('file:///<SKILL_DIR>/scripts/export_getcourse.mjs')).default;
var job = X.newJob({spreadsheetId, language, roots});
// language: 'ru' или 'en'; roots: [{kind:'course'|'bonus', url, title}, ...]
```

В Windows URL начинается с `file:///C:/...`. `roots` — все подтвержденные корни пакета, не только первый. Одноименные уроки с разными URL не объединяются. Две формы адреса одного урока (`/view/id/N` и `/view?id=N`) считаются одним источником. Один источник, встречающийся в нескольких тренингах одного блока, сохраняет все пути; курс и бонусный блок остаются раздельными.

Рабочий файл — `C:/Codex/<текущий проект>/getcourse-export/checkpoint.json`. Использовать существующий каталог проекта под `C:/Codex`, либо создать отдельный. На диск сохраняются только извлеченные учебные данные и состояние, а не страницы целиком, учетные данные или подписанные адреса видеоплееров. Рабочие файлы не помещать в папку установленного скилла и не публиковать в GitHub.

```js
await X.saveJob(statePath, job); // атомарная замена файла в Node/cua_repl
job = await X.loadJob(statePath, {spreadsheetId, language});
nodeRepl.write(X.summary(job));
```

Сохранять после каждого списка, урока, решения по изображению, подготовки записи и проверки записи. В двух средах не редактировать разные копии состояния одновременно: после изменения через `functions.exec` заново загрузить checkpoint в `cua_repl`. `store()` не заменяет checkpoint: он не переживает перезапуск сессии.

## 2. Один раз подтвердить области страницы

Посмотреть DOM/видимое содержимое первого тренинга и первого урока каждого шаблона. Не использовать `document.body.innerText` как учебный текст. В проверенном шаблоне GetCourse встречаются такие настройки; применять их только после подтверждения на текущих страницах:

```js
var listConfig = {
  rootSelector: '.stream-table, .lesson-list', titleSelector: 'h1',
  linkTitleSelector: '.stream-title, .title',
  entrySelector: '.lesson-list > li, .stream-table tr.training-row',
  excludeSelectors: ['.lesson-list__video-watched']
};
var lessonConfig = {
  rootSelector: '.lite-page, [class^="mission-deadline-removable-block-"] > h3, .lesson-mission-text',
  titleSelector: '.lesson-title-value',
  excludeSelectors: ['.o-lt-lesson-comment-block', '.lesson-send-answer-block',
    '.self-answers', '.o-lt-lesson-feedback-block']
};
```

`.lite-page` может содержать и урок, и ответы учеников. Поэтому проверить исключения обязательно: описание, материалы и текст задания должны остаться; ответы, формы отправки, оценки и меню — исчезнуть. Не исключать произвольные абзацы по словам вроде «материалы» или «задание». При другом шаблоне подобрать фактически наблюдаемые селекторы, а не возвращаться к ручному переписыванию всех текстов.

`paginationSelector`, если нужен, задается по фактическим ссылкам страниц списка. Проверить раскрытые модули, пагинацию, вкладки и «показать еще» через браузер; скрипт сам ничего не нажимает. Отсутствие `review` не доказывает полноту страницы. Скрытые CSS-блоки и закрытые вкладки могут потребовать отдельного раскрытия и повторного захвата. Не нажимать отправку ответа, изменение прогресса, покупки или редактирование.

После `tab.goto(observedUrl)` дождаться известного контейнера через документированный `locator(...).waitFor({state:'visible'})`, затем получить данные и короткую сводку:

```js
var captured = await tab.playwright.evaluate(
  '(' + capturePage.toString() + ')(' + JSON.stringify(listConfig) + ')'
);
nodeRepl.write({status:captured.status, title:captured.title,
  links:captured.links.length, images:captured.media.length, review:captured.review});
```

Строка содержит только доверенный установленный код и JSON настроек; код из страницы никогда не выполнять. В этом браузерном API используется выражение с вызовом функции, а не одна строка объявления `function capturePage(...)`. Не выводить полный `captured`, DOM, HTML или список всех URL на каждом шаге. Для проверки показывать выборочные начало/конец и исключения.

## 3. Реестр и тексты

`X.addListing(job, captured, {reviewed:true, reason:'...что проверено...'})` принимает только проверенную полную страницу списка. `X.inventory(job)` возвращает `lessons`, `issues`, `unavailable`, `trainings`, `ready`. Обходить `unvisited_training` в исходном порядке, пока не собраны все уровни бонусов и курсов. Сохраненные списки не обходить повторно при продолжении того же задания. Навигацию по уже обнаруженным ссылкам одинакового шаблона можно выполнять короткими последовательными пакетами в одном вызове инструмента, сохраняя состояние после каждой страницы.

- Ссылки из наблюдаемого буквального `onclick="location.href='...'"` тоже собираются: так может выглядеть скрытый от учеников, но доступный администратору урок. Скрипт не исполняет обработчик.
- `unlinked` означает запись списка без понятного URL. Проверить ее отдельно; либо найти фактическую ссылку и добавить в `captured.links`, либо документировать `status:'no_access', reason:'...'`. Не удалять запись молча. Счетчик недоступных учитывает такие записи отдельно.
- Для временных ошибок — одна повторная попытка после проверки состояния. Не прерывать весь доступный материал из-за одного закрытого тренинга: `X.markTrainingError(job, observedUrl, 'no_access'|'load_error', reason)`. Он останется в `inventory.issues`, а итог будет неполным.
- `ready` разрешает обработку обнаруженной доступной части, но не означает, что отсутствуют ошибки доступа.

После полного реестра последовательно захватывать уроки с `lessonConfig`. `status:'login_required'` или `missing_content` не считать пустым уроком; восстановить вход/загрузку/селектор. `review` показывает закрытые элементы, iframe и нестандартные визуальные объекты. Видео не транскрибировать; учебное содержимое другого iframe отдельно проверить доступным браузерным способом. Изображения/текст внутри iframe не представлены автоматически в родительском DOM. Расположение блоков, вложенных списков и таблиц сверить с видимой страницей, особенно при сложной верстке.

```js
X.putLesson(job, lesson.id, captured, {
  reviewed:true, reason:'Описание и задание полные; iframe — видео; ответы исключены'
});
await X.saveJob(statePath, job);
```

`putLesson` проверяет соответствие ID урока после редиректа. Название должно быть точным; оно хранится отдельно от тела и не должно повторяться в первой строке тела. Не удалять одинаковые фразы внутри текста и между уроками. Пустое тело допустимо только после фактической проверки урока. Для ошибки урока — `X.markError(job, lesson.id, 'no_access'|'load_error', reason)`.

Повторный захват точно того же текста сохраняет подтверждение записи. Изменение текста снимает подтверждение, сохраняя прежние координаты как `staleReceipt`; изменение списка изображений снова открывает их проверку. Это не разрешение автоматически заменять уже переведенный текст.

## 4. Изображения остаются обязательной частью

Каждый кандидат в `job.records[lesson.id].media` начинается с `decision.status='pending'`. Это еще не выбранное для выгрузки изображение. `visible:false` не означает автоматически «декоративное»: проверить lazy-load/вкладку/скрытый служебный элемент. URL/имя/размер не доказывают визуальное совпадение. `alt` и `title` остаются метаданными, не превращаются в OCR. Из `candidates` выбрать подтвержденный доступный оригинал; не конструировать неизвестные адреса вместо реально найденных.

Codex применяет смысловой фильтр и правило одного файла/одного OCR на проект из SKILL.md, распознает и визуально проверяет текст, загружает выбранное изображение, перечитывает результат. Только после действия вызвать:

```js
X.decideMedia(job, lesson.id, image.id, {status:'excluded', reason:'Проверено: декоративное фото'});
X.decideMedia(job, lesson.id, image.id, {
  status:'reused', reason:'Сверены визуал и текст с существующим результатом',
  fileUrl, ocrRange, fileVerified:true, ocrVerified:true
});
X.decideMedia(job, lesson.id, image.id, {
  status:'saved', reason:'Новый файл и OCR проверены', fileUrl, ocrRange,
  sheetTitle:'МАТЕРИАЛЫ (картинки на перевод)', fileVerified:true, ocrVerified:true
});
// Для незавершенного: status:'needs_manual_check' или 'blocked' и конкретная reason.
```

Выбрать одну подходящую операцию, не выполнять все примеры подряд. Частично готовые файл/текст записать в решении `blocked` с имеющимися `fileUrl`/`ocrRange`, затем дополнить недостающее. Решения сохранять в checkpoint. OCR размещать по основному скиллу; `prepareWrite` предназначен только для двухстрочных уроков и никогда не смешивает их с OCR.

## 5. Пакетная запись через подключенные инструменты

Найти актуальные схемы Google-инструментов, метаданные и заголовки листов, размеры сетки, объединения, текущие значения и переводы. В пустом листе отдельно подготовить `РУС`/`EN`. Для существующего листа подтвердить соответствие уроков и строк по URL/ведомости, а не одному совпавшему заголовку. Проверить весь занятый диапазон, чтобы не добавить второй экземпляр уже выгруженного урока и не оставить незамеченный старый хвост.

В `functions.exec` один раз загрузить доверенный модуль через `exec_command` без вывода его текста:

```js
const r = await tools.exec_command({
  cmd:"Get-Content -LiteralPath '<SKILL_DIR>/scripts/export_getcourse.mjs' -Encoding UTF8 -Raw",
  max_output_tokens:18000
});
if (r.exit_code !== 0 || r.output.includes('tokens truncated')) throw Error('Incomplete module');
store('gc.code',r.output);
const X = new Function(r.output.replace(/\nexport default GetCourseExport;\s*$/,'')+'\nreturn GetCourseExport;')();
```

В следующих вызовах восстановить `X` из `load('gc.code')`. `new Function` — только для доверенного локального кода, не для данных. `saveJob/loadJob` требуют Node; в `functions.exec` использовать инструменты чтения/записи файлов. Загрузить checkpoint как JSON через `exec_command` с достаточным лимитом, проверить отсутствие обрезки, оставить объект в `store`. Для большого checkpoint читать по файлу в Node и отдавать отдельные порции; не печатать весь JSON модели.

Данные из коннектора должны идти прямо в скрипт, а не через переписывание моделью. Использовать `get_spreadsheet_cells` с `userEnteredValue,userEnteredFormat,effectiveFormat`. Из актуального ответа выделить ресурс текущего листа (`properties`, `data`, `merges`), при необходимости присоединить метаданные из отдельного ответа. Примеры ниже предполагают уже распакованный ресурс, не оболочку MCP.

```js
const before = X.snapshot(sheetResource, startRow, lessonIds.length * 2);
const prepared = X.prepareWrite(job, lessonIds, before, {reviewed:true});
X.stageWrite(job, prepared);
// СНАЧАЛА сохранить job с pending, затем передать prepared.requests подключенному batchUpdate.
```

Брать до 10 последовательных уроков одной вкладки за пакет (меньше при большом тексте). Между пакетами перечитывать значения и оформление. Сохранять пары «название + тело» целиком. Для пропущенного/недоступного урока вести явное соответствие строк и ведомость, не сдвигать существующие переводы. Не считать один огромный запрос обязательной оптимизацией.

`prepareWrite` работает с пустым диапазоном или точным совпадением текущего исходника. Пишет literal `stringValue` только в A (RU) или B (EN), даже если текст начинается с `=`. Желтый, жирный, центрированный заголовок оформляет по A:B. Текстовую строку очищает только от желтой заливки; остальные свойства сохраняет. Не вставляет/удаляет строки, не очищает лист или хвост и не меняет соседние значения/формулы.

Другой текст, перевод напротив пустого исходника, формула в исходной колонке, объединения, неверная вкладка, недостаточная сетка или конфликт старых координат вызывают отказ. Нельзя обходить отказ поддельным пустым `before` или удалением receipt: сначала подготовить конкретное соответствие строк по правилам скилла. При изменившемся исходнике безопасное обновление существующей пары выполняется отдельно после проверки связи с переводом.

Для сохранения состояния из `functions.exec` можно использовать `apply_patch`, сформировав JSON программно; `Add File` здесь записывает полный актуальный checkpoint по заранее выбранному локальному пути. Проверить успешность записи **до** обращения к Sheets. Пример без shell-интерполяции пользовательского текста:

```js
await tools.apply_patch('*** Begin Patch\n*** Add File: '+statePath+'\n'
  + JSON.stringify(job,null,2).split('\n').map(line=>'+'+line).join('\n')
  + '\n*** End Patch');
```

Сохранение должно успешно завершиться; после ошибки не продолжать запись. Не печатать подготовленные запросы/весь checkpoint. После успешного `batchUpdate` заново прочитать **тот же A:B диапазон** с теми же CellData-полями и метаданными:

```js
const after = X.snapshot(rereadSheetResource, startRow, lessonIds.length * 2);
const result = X.confirmWrite(job, prepared.id, after);
// Сохранить checkpoint; выводить только result и X.summary(job).
```

Сравниваются точный текст, соседние `userEnteredValue` (включая формулы), желтый/жирный/центрированный заголовок и отсутствие желтого у тела. До успешной проверки batch остается в `job.pending`; продолжение сначала сверяет его с таблицей, а не пишет урок повторно. Если запись точно не дошла, перечитать диапазон, проверить отсутствие чужих изменений и повторить те же сохраненные запросы. При отличиях — остановить конкретный пакет и объяснить конфликт, не перезаписывать вслепую.

## 6. Продолжение и завершение

Для продолжения прерванного задания загрузить checkpoint этого проекта/языка, перепроверить текущие корни и вкладки по карточке. Проверить `pending` чтением; подтвержденные диапазоны перечитать пакетно перед пропуском готовых уроков. Уже проверенные неизменные уроки не требуют нового OCR или повторной записи. Новый самостоятельный запуск после изменения материалов требует обновления реестра/затронутых страниц; старый checkpoint не доказывает, что источник навсегда неизменен.

`summary.complete` означает полноту только сохраненного состояния, а не независимую проверку актуальности сайта, Drive и таблицы. Финальную выборочную проверку начала/конца обоих блоков, необычных страниц, ссылок Drive, общей папки, OCR и ошибок выполнить по SKILL.md. Не писать «всё готово» при `pending`, `blocked`, `needs_manual_check`, `no_access`, `load_error` или незавершенном вложенном тренинге. Отчет: отдельные счетчики курса/бонусов, подтренинги, новые/переиспользованные картинки, языковая колонка, диапазоны и конкретные остатки.

## Проверка при изменении кода

`node --test '<SKILL_DIR>/scripts/export_getcourse.test.mjs'` — автономные тесты без сети и изменения таблиц. Тестовые `scripts/fixtures/lesson.html` и `login.html` можно открыть через локальный HTTP-сервер и прогнать тем же DOM-сборщиком: проверить списки с start/value, таблицу, повторы, скрытый/видимый пароль, исключение ответов, lazy/srcset/picture/CSS, закрытый details и урок без обычной ссылки. Затем выборочно проверить реальные страницы авторизованного GetCourse **без записи в рабочую карточку**. Проверка только текста не считается выполненной обработкой изображений.
